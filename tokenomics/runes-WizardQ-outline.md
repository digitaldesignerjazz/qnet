# Runes (Wizard Q) Outline

**Status**: Initial draft / work in progress

## Overview
Runes under the Wizard Q framework represent extensible, programmable assets and logic within the QNET protocol. They extend beyond simple tokens to enable custom rules, conditions, and interactions.

## Design Goals
- Flexible asset creation with embedded logic
- Strong integration potential with mesh networking actions and AI agent behaviors
- Privacy and security considerations suitable for decentralized environments
- Composability with XCoin/QCoin and other runes

## Planned Capabilities

### Asset Types
- Transferable runes with custom metadata and rules
- Conditional runes (e.g., time-locked, event-triggered, or mesh-state dependent)
- Utility runes for specific protocol or application functions

### Logic & Execution
- On-chain or hybrid execution models
- Interaction with mesh primitives (e.g., triggering on message receipt or file transfer completion)
- Agent swarm interaction patterns (e.g., runes as task rewards or coordination tokens)

### Privacy Features
- Optional privacy-preserving rune designs
- Integration considerations with Tor/I2P and mesh privacy layers

## Integration Examples
- A rune that rewards successful mesh peering or data contribution
- Conditional runes used by AI agents for automated coordination or payments
- Wizard Q runes that represent access rights or capabilities in the broader ecosystem

## Open Questions
- Execution environment (on-chain VM vs hybrid)
- Degree of integration with mesh state vs pure on-chain logic
- Security model for custom rune logic

## Next Steps
- Detailed rune specification and examples
- Use-case catalog (mesh incentives, AI tasks, creative/immersive applications)
- Security and formal analysis
